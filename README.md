# ClientFlowCRM Практическая работа 4

**Практики DevOps в современных методологиях разработки**  
Цибулин Владислав Владимирович, ИКБО-22-23

Основной вариант задания со страницы 118 методического пособия.
Учебный конвейер Jenkins собирает пакет спецификаций ClientFlowCRM,
проверяет его и моделирует развёртывание в staging и production.

Репозиторий: https://github.com/VlTs-dev/ClientFlowCRM-Practice4

## Что реализовано

1. Получение Jenkinsfile и файлов проекта из Git.
2. Создание архива `clientflowcrm.tar.gz`, SHA256 и метаданных сборки.
3. Проверка контрольной суммы, состава архива, имени проекта и пяти модулей.
4. Копирование одного и того же пакета в каталог окружения staging.
5. Smoke-проверка результата учебного развёртывания.
6. Ручное подтверждение выпуска в Jenkins.
7. Копирование пакета в production и повторная smoke-проверка.
8. Архивирование результатов, обработка успеха и ошибки, очистка workspace.
9. Передача демонстрационного токена через Jenkins Credentials.

Вместо работающего CRM-сервера развёртываются файлы учебного пакета.
Smoke-проверки проверяют эти файлы, а не доступность веб-приложения.
Для основного варианта пособие допускает имитацию сборки и развёртывания.

## Запуск на Windows

На исходном компьютере используйте файл запуска рядом с отчётом: он использует
уже скачанные компоненты и настроенный Jenkins с сохранёнными сборками.

Для самостоятельного запуска копии проекта:

1. Убедитесь, что установлен Git for Windows и в системе есть `tar.exe`
   (проверенная среда содержит оба инструмента).
2. Запустите `START.cmd`. В первый раз потребуется интернет для загрузки
   Jenkins 2.580.3, переносной Java 21 и плагинов. Архивы Java, Jenkins и
   установщик плагинов проверяются по SHA256.
3. Дождитесь готовности Jenkins по адресу `http://127.0.0.1:8088/`.
4. Логин `student`, пароль сохранён в `.jenkins-home/local-access.json`.
5. Откройте задание `ClientFlowCRM-CICD` и запустите сборку.
6. На этапе «Подтверждение» нажмите «Выпустить».
7. Проверьте `SUCCESS` и архивы в разделе артефактов сборки.

Jenkins и локальный Git-сервер слушают только `127.0.0.1`.
Системная Java не изменяется, служба Windows и автозапуск не создаются.
Для остановки выполните `Stop-Practice.ps1`.

## Репозиторий GitHub

Исходные файлы размещены в публичном учебном репозитории
https://github.com/VlTs-dev/ClientFlowCRM-Practice4.
Веткой проекта является `main`. Jenkins получает оттуда Jenkinsfile и
сценарии. Чтение репозитория не требует пароля GitHub.

Внешний репозиторий содержит только исходные файлы. Локальный пароль
администратора, домашний каталог Jenkins, runtime и результаты сборок
не входят в исходный код и исключены из архива исходного проекта.

В Jenkins откройте `ClientFlowCRM-CICD` → `Configure` → `Pipeline`:

- Definition: `Pipeline script from SCM`;
- SCM: `Git`;
- Repository URL: `https://github.com/VlTs-dev/ClientFlowCRM-Practice4.git`;
- Branch Specifier: `*/main`;
- Script Path: `Jenkinsfile`.

Настройка выполняется автоматически сценарием Start-Practice.ps1.
Для локальной демонстрации без GitHub можно явно передать
`-RepositoryUrl ''`: тогда запускается локальный HTTP-сервер Git.

## Учебная ошибка и уведомления

Параметр `SIMULATE_FAILURE=true` вызывает управляемую ошибку после проверок
пакета. Последующие этапы пропускаются, выполняется обработчик `failure`.
Повторный успешный запуск демонстрирует восстановление (`fixed`).

Email по умолчанию выключен. Для реальной отправки предварительно настройте
SMTP в Jenkins, затем задайте `SEND_EMAIL=true` и `NOTIFY_EMAIL`.
Во время локальной проверки письма не отправлялись.

## Учётные данные

Скрипт настройки создаёт учебные секретные данные с ID
`clientflowcrm-demo-token`. Это демонстрационное значение, которое не даёт
доступа к внешним системам. В Jenkinsfile оно получается через `credentials`,
а в логе отображается только факт передачи. Пароль локального администратора
создаётся случайным и в исходные файлы репозитория не входит.
